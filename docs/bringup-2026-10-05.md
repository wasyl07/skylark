# Bring-up record, 2026-10-05

First bring-up of the Linux image on a BeagleBone Black with the Skylark cape
(rev 1). This file records what was tested, the results, and the state the
board was left in. The requirement IDs refer to [FUNCTIONS.md](FUNCTIONS.md).

| Item | Value |
|---|---|
| Board | BeagleBone Black + Skylark cape rev 1 |
| SD card | 16 GB (14.7 GiB) |
| Image | A/B image from `br2-skylark/`, `SKYLARK_VERSION=0.1.0`, built from `7ea67043-dirty` (the changes later committed as `4cb27f1a..9928d537`) |
| PC side | PEAK PCAN-USB as `can0`, USB-UART adapter on UART4 as `/dev/ttyACM1` |

## Board state at the end of the session

- Boots from the **SD card** (A/B image), currently running **slot B**. Both
  slots hold the same image and are marked good; `BOOT_ORDER=B A`.
- The **eMMC** still holds the old single-slot image (see
  [buildroot-legacy.md](buildroot-legacy.md)). Its `MLO` is renamed to
  `MLO.disabled`, so the ROM skips the eMMC and boots the SD card. To boot the
  eMMC again, rename it back from the SD system:

  ```sh
  mount /dev/mmcblk1p1 /mnt && mv /mnt/MLO.disabled /mnt/MLO && umount /mnt
  ```

- Network: DHCP, currently `192.168.1.10`, also `skylark.local`.
- Login: root / `skylark` (development password), SSH key of the development PC
  in `/data/ssh/root/authorized_keys`.

## Cape rev 1 issues found

These are hardware problems for the next cape revision.

1. **DS1307 RTC does not keep time** (U3, crystal Y1, coin cell BT1).
   The chip answers at 0x68 on I2C2 and accepts writes. After clearing the
   clock-halt bit the seconds advance for a few seconds, then stop. Over a
   60 s measurement the RTC advanced 0 s. Likely causes, in order:
   - VBAT (TP25) missing or low: no coin cell, or a flat one.
   - Crystal Y1 not the 12.5 pF load type the DS1307 needs.
   Check VBAT on TP25 and the Y1 part number first.
2. **I2C2 pull-ups go to 5 V** (R22, R23), while the AM335x I2C2 pins are
   3.3 V and not 5 V tolerant. Pull them up to 3.3 V. This may also be why the
   first I2C2 access after boot sometimes times out (`omap_i2c 4819c000.i2c:
   controller timed out`); the software now retries.
3. **EEPROM U1 (CAT24C256) does not answer** on I2C2 at any address
   0x50-0x57. Check the address pins, power, and assembly.

## Problems found and fixed in software

| Problem | Fix |
|---|---|
| U-Boot refused `boot.scr` ("Wrong image format for source command") and fell back to the eMMC | `CONFIG_LEGACY_IMAGE_FORMAT=y` (signed-image support turns it off) |
| Build failed in systemd (`SIOCGSTAMPNS_OLD`): stable Bootlin toolchain has 4.19 headers, networkd needs >= 5.4 | Bootlin bleeding-edge toolchain; `skylark-config` now depends on headers >= 5.4 |
| `/data` unmounted again 6 s after first boot (after growing p4) | `udevadm settle` at the end of `growdata.sh` |
| RTC restore failed on the first I2C read after boot | RTC accesses retried 3 times |
| RTC sync unit hit systemd's start limit (path unit re-triggered while the flag file existed) | replaced by a 10 min timer |
| SSH host key and `authorized_keys` changed with every slot switch | moved to `/data/ssh` |
| RAUC could not load per-slot status files | central status file `/data/rauc.status` |
| A failed overlay apply would boot a half-patched device tree | `boot.cmd` reloads the plain DTB |
| Legacy image: `root=/dev/mmcblk${devnum}p2` became `root=/dev/mmcblkp2` and the board hung | `root=PARTUUID=534b594c-02` with a fixed MBR disk signature |
